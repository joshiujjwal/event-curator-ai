# EventCuratorAI — Feature Specification

## Overview

EventCuratorAI is an AI-powered event discovery platform that:
1. **Aggregates** IRL events from multiple external sources (Eventbrite, Meetup, Facebook Events, Ticketmaster, venue RSS/ICS feeds)
2. **Personalizes** a ranked event feed per user using semantic embeddings + cosine similarity
3. **Summarizes** events using GPT-4o-mini so users get a 2-sentence TL;DR without reading marketing copy
4. **Unifies** the discovery UX — one place to find everything happening locally

### Problem Statement

Finding local events requires checking 5+ apps/sites. Each has its own algorithm, interface, and audience. There's no single place that: (a) aggregates across sources, (b) learns your taste, (c) cuts through the noise.

## Functional Requirements

### Event Ingestion
- [ ] Ingest events from Eventbrite API (OAuth app token)
- [ ] Ingest events from Meetup GraphQL API
- [ ] Ingest events from Facebook Events Graph API (requires user token for private events)
- [ ] Ingest events from Ticketmaster Discovery API (public)
- [ ] Parse `.ics` / RSS feeds from venue websites (configurable list)
- [ ] Upsert events: deduplicate on `sourceId + sourceName`, update if `updatedAt` changed
- [ ] Ingest runs on a schedule (every 4 hours) via BullMQ jobs
- [ ] Each adapter implements the `SourceAdapter` interface

### Event Data Model
- [ ] Events have: `id`, `title`, `description`, `startAt`, `endAt`, `location` (address + lat/lng), `url`, `imageUrl`, `price` (min/max/currency), `categories` (string[]), `sourceId`, `sourceName`, `embedding` (vector), `aiSummary`, `createdAt`, `updatedAt`
- [ ] Location stored as: `address: string`, `city`, `state`, `lat: Float`, `lng: Float`
- [ ] Price: `free: boolean`, `minPrice: Float?`, `maxPrice: Float?`, `currency: String?`

### User Profiles & Interests
- [ ] Users authenticate via Google or GitHub OAuth (NextAuth.js)
- [ ] Users select interest tags on onboarding (min 3): e.g. "jazz", "tech talks", "outdoor sports", "art gallery", "food festivals"
- [ ] User interest tags are embedded and stored as `userEmbedding: vector(1536)` in the `User` model
- [ ] Updating interests triggers re-computation of `userEmbedding`
- [ ] Users can save events to a personal list
- [ ] Users can mark events as "not interested" (negative signal, excluded from future ranking)

### Personalized Discovery Feed
- [ ] `GET /api/events` returns events ranked by cosine similarity between `event.embedding` and `user.userEmbedding`
- [ ] Feed supports pagination (cursor-based)
- [ ] Feed supports filters: `source`, `dateFrom`, `dateTo`, `category`, `maxDistanceKm`, `free`
- [ ] Unauthenticated users see a chronological feed (no personalization)
- [ ] Ranked feed refreshes when user updates interests

### AI Summaries
- [ ] Each event gets a 2-sentence AI summary generated by GPT-4o-mini
- [ ] Summary is cached in DB, regenerated only if `description` changes
- [ ] Summarizer respects OpenAI rate limits (queued via BullMQ `summarize` job)

### Frontend
- [ ] `/discover` — main feed with search, filters, ranked cards
- [ ] `/event/[id]` — event detail: title, AI summary, full description, map, source link
- [ ] `/profile` — interest management, saved events, not-interested list
- [ ] Auth pages: `/login`, `/signup`

---

## Non-Functional Requirements

- [ ] API p95 latency < 500ms for `/api/events` (ranked feed, cached embeddings)
- [ ] Ingest pipeline processes 1,000 events/hour without exceeding API rate limits
- [ ] Zero PII stored beyond what NextAuth.js requires (name, email, avatar)
- [ ] All API keys stored in env vars, never committed
- [ ] TypeScript strict mode — no `any` in production code
- [ ] Test coverage > 80% for `src/lib/` (unit + integration)

## Data Models (Prisma)

```prisma
model Event {
  id          String   @id @default(cuid())
  title       String
  description String?
  startAt     DateTime
  endAt       DateTime?
  url         String
  imageUrl    String?
  address     String?
  city        String?
  state       String?
  lat         Float?
  lng         Float?
  free        Boolean  @default(false)
  minPrice    Float?
  maxPrice    Float?
  currency    String?
  categories  String[]
  sourceId    String
  sourceName  String
  aiSummary   String?
  // embedding stored via pgvector extension
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  savedBy     UserSavedEvent[]
  interactions UserEventInteraction[]

  @@unique([sourceId, sourceName])
  @@index([startAt])
  @@index([city])
}

model User {
  id            String   @id @default(cuid())
  email         String   @unique
  name          String?
  image         String?
  // userEmbedding stored via pgvector extension
  interests     String[]
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  savedEvents   UserSavedEvent[]
  interactions  UserEventInteraction[]
  accounts      Account[]
  sessions      Session[]
}

model UserSavedEvent {
  userId    String
  eventId   String
  savedAt   DateTime @default(now())
  user      User   @relation(fields: [userId], references: [id])
  event     Event  @relation(fields: [eventId], references: [id])

  @@id([userId, eventId])
}

model UserEventInteraction {
  userId    String
  eventId   String
  type      InteractionType
  createdAt DateTime @default(now())
  user      User   @relation(fields: [userId], references: [id])
  event     Event  @relation(fields: [eventId], references: [id])

  @@id([userId, eventId])
}

enum InteractionType {
  SAVED
  NOT_INTERESTED
  CLICKED
  ATTENDED
}
```

## API Design

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/events` | Optional | Ranked feed (personalized if authed) |
| GET | `/api/events/[id]` | No | Event detail |
| POST | `/api/events/[id]/save` | Required | Save/unsave event |
| POST | `/api/events/[id]/dismiss` | Required | Mark not-interested |
| GET | `/api/user/interests` | Required | Get current interest tags |
| PUT | `/api/user/interests` | Required | Update interests, re-embed |
| GET | `/api/user/saved` | Required | List saved events |
| POST | `/api/admin/sync` | Admin | Trigger manual ingest |

### `GET /api/events` Query Params
```
?cursor=<cuid>        # pagination cursor
&limit=20             # default 20, max 100
&source=eventbrite    # filter by source
&dateFrom=2024-01-01
&dateTo=2024-01-31
&category=music
&free=true
&lat=37.7749&lng=-122.4194&maxDistanceKm=25
```

## Source Adapter Interface

```typescript
export interface RawEvent {
  sourceId: string
  sourceName: string
  title: string
  description?: string
  startAt: Date
  endAt?: Date
  url: string
  imageUrl?: string
  address?: string
  city?: string
  state?: string
  lat?: number
  lng?: number
  free: boolean
  minPrice?: number
  maxPrice?: number
  currency?: string
  categories: string[]
}

export interface SourceAdapter {
  name: string
  fetchEvents(options: FetchOptions): Promise<RawEvent[]>
}

export interface FetchOptions {
  city?: string
  lat?: number
  lng?: number
  radiusKm?: number
  dateFrom?: Date
  dateTo?: Date
  maxResults?: number
}
```

## Open Questions

- [ ] **Facebook Events**: Graph API requires a user token for private events — is OAuth-on-behalf-of-user feasible, or do we limit to public events only?
- [ ] **Geo-ranking**: Should distance be blended into the AI ranking score, or kept as a hard filter?
- [ ] **Event freshness**: How to surface events happening "this weekend" more prominently without breaking personalization ranking?
- [ ] **Duplicate detection**: Two sources may list the same event (e.g., a concert on Eventbrite AND Ticketmaster) — do we merge or show both?
- [ ] **Rate limits**: Meetup allows 10 req/min — does BullMQ throttle adequately or do we need a custom rate limiter per adapter?
